# Components

Registered in `src/theme/MDXComponents.tsx`, so every one is available in any `.md` or
`.mdx` without an import. Conventions follow `DESIGN.md`.

## `<Evidence>` — §5.3

An evidence id that resolves to its record.

```jsx
<Evidence id="E-016" />                          {/* E-016, linked, record on hover */}
<Evidence id="E-016">the whitened run</Evidence> {/* labelled */}
<Evidence id="f-R-010" />                        {/* findings are namespaced f- */}
<Evidence id="t-T-067" />                        {/* threads are namespaced t- */}
```

Data comes from `data/evidence.yml`, generated by
`ai/edit-slice/agents/engineer/workspace/build_ledger.py` from the same parse that builds
`notebook/edit-slice/ledger.md` — so a link and its target cannot disagree. **Do not edit
`evidence.yml`;** regenerate it.

An id with no record renders in oxide with a dotted rule rather than as plain text. A dead
reference that looks alive is how a broken link survives three drafts.

## `<Margin>` — §5.1

A side note. Floats into the gutter above 1100px; falls inline directly after its
anchoring paragraph below that, still in the apparatus face and still subordinate.

```jsx
Possession is measured over a type-matched pool.<Margin>50 candidates, seed 1538. Absolute
levels move with pool size; only the ordering is robust.</Margin>
```

No superscript and no reference marker — the note sits beside its line and that is the
whole mechanism. Put *apparatus* here: how a number was obtained, what was excluded, which
record it came from. If the sentence would change the reader's conclusion, it belongs in
the prose.

## `<Figure>`

```jsx
<Figure caption="What the figure shows, and what it does not.">
  {/* inline SVG */}
</Figure>
```

Numbered automatically by CSS counter, so numbering survives reordering. Captions render
below the frame. Do **not** write "Figure 1 —" into the caption; it is added.

## `<Claim>`

The claim-and-its-fate block. Existing API, used in 5 files:

```jsx
<Claim
  label="What the project claims"
  superseded={<>The version that was withdrawn.</>}
  record={{ "Why it failed": "…", "Replaced by": "…", Evidence: "E-015, 42 chains" }}
>
  The claim as it now stands.
</Claim>
```

`DESIGN.md` §5.4 proposes a different API (`status`, `stated`, `because`, `replacedBy`,
`evidence`). Adopting it means editing every call site, which §7 forbids; resolve that
conflict before changing this component.

## `<Cite>` / `<References>`

```jsx
<Cite id="holtzman2021surface" />            {/* (Holtzman et al., 2021) */}
<Cite id="meng2022rome" narrative />         {/* Meng et al. (2022) */}
<References project="edit-slice" />          {/* renders its own heading */}
```

Resolved from `data/papers.yml`. Entries carry `verified: true` only when the venue and id
have been checked against the source — an unverified citation is marked in the UI, because
a secondhand reference that looks identical to a checked one is how a wrong venue survives
three drafts.
