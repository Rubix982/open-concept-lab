## 2. The definitions page (write this first)

Four declarations, one or two sentences each. This is the whole artifact.

**A fact is a behavioral unit defined by its probe set.** Not a parameter-level
object. The ROME/MEMIT inheritance implies discrete editable units; the
mechanism section implies superposition and shared parameters. Those conflict.
Resolution: the dependency graph is over *behaviors*; superposition is the
explanation for why edges leak, not the ontology.

**Name the dependency relation.** Syntactic reference, type-level entailment,
and semantic dependency are three different relations, currently conflated
under "the compiler is the oracle." Pick one. State that the compiler yields a
**decidable lower bound** on true dependency, not the full graph. This is a
strength — a decidable subset is what makes it usable. Claiming completeness is
what makes it indefensible.

**Scope to the propositional layer.** Signatures, ownership, conventions,
invariants — things expressible as assertions, where the graph stays decidable.
Bracket the procedural layer (capacity to write architecture-consistent code)
explicitly as out of scope. That's clarity, not retreat.

**The graph is a normative audit spec, not a model of the network.** An LM is
not structured like a graph, and that doesn't matter. The graph specifies what
is *required* of the network. Its boundary is a choice, not a fact to discover —
which dissolves the "where does the chain start and end" problem at the root.
Coherence is bounded: no contradiction reachable within *k* hops, forward or
backward, of the edited node. **State k.** Drop "inevitable" — full world-model
revision is undeliverable and will get hit.

## 3. The new idea: backward probing

Everything in the literature probes **forward** — edit a fact, check its
consequences. Nobody probes **backward** toward the grounds that made the
original fact hold.

Eiffel-Tower-into-Rome: dependents get some attention, but the model still
believes Gustave Eiffel built it for the 1889 Paris Exposition. Ask which city
hosted the 1889 World's Fair and the contradiction is reachable only by walking
upstream.

This is a third category, not covered by the existing two:

- **update-forgetting** (correct) — a fact that should have been replaced was
- **damage-forgetting** (harmful) — an unrelated dependent broke
- **orphaned justification** (new) — the edit left its own grounds intact and
  now contradictory

The jenga metaphor needs revision in light of §6 below: the piece may not have
left the tower at all. The path to it moved.

## 4. Depth as the independent variable

"Where does the chain end" was being treated as something to settle before
measuring. It can't be settled — transitive closure reaches everything. So make
depth the variable instead: edit a node, probe at hop 1, 2, 3 along the graph,
measure consistency per shell. The output is a decay curve, and the boundary
becomes an empirical finding rather than a definition.

Out-degree at the edited node and probe-shell depth are then **separate**
variables, varied independently — which separates breadth-driven failure from
distance-driven failure. Heterogeneous edge types stop being a problem and
become a factor to stratify on.

## 5. Probe discovery (the circularity problem)

Hand-writing probes is circular: you enumerate what you already believe depends
on the fact, so the graph you measure is the graph you assumed. You can confirm
your picture, never discover outside it.

**Read questions off the oracle.** This is the real argument for the code
domain. Eiffel Tower has unbounded probe dimensions (history, weather,
construction, tourism) with no principled enumeration. A formal language has a
**closed set of edge types**: calls, imports, type instantiation, subtyping,
field access, module exports. Each edge type templates a question mechanically.
Probe discovery collapses into edge-type enumeration — finite and inspectable.
The graph isn't just ground truth for what should propagate; it's the *question
generator*.

Consequence to state: out-degree is measured **relative to the edge-type
vocabulary**. Different vocabularies give different branching factors for the
same node. Report the vocabulary or the number isn't reproducible.

**Invert for discovery.** Templates only find anticipated damage. For the rest:
don't start from questions, start from movement. Run a broad question set
unrelated to the edit, rank by output shift, inspect the top movers, then
explain why they moved. Measure-then-probe, not probe-then-measure.

Templates give coverage. The sweep gives surprise. Saturation on the first means
the observable graph is covered; persistent hits on the second mean the edge
vocabulary is missing a relation.

## 6. Movement sweep — mechanics

**Metric.** KL from pre-edit to post-edit next-token distribution at the final
position, as unsigned magnitude (needs no reference answer, which is what makes
sweeping unlabeled prompts possible). Carry three signed quantities alongside:

- log-prob of the pre-edit correct answer — for grounds probes this should *not* fall
- log-prob of the newly injected object token — rising where it shouldn't is leakage
- entropy change — rising means confusion rather than reassignment

Multi-token answers: teacher-force and sum log-prob deltas, don't read position one.

**Nulls — the part that gets skipped.** Every perturbation moves everything a
little, so raw KL rankings are dominated by fragile prompts. Two controls:

1. null distribution over unrelated prompts, so significance = exceeding a high
   percentile rather than being nonzero
2. apply a *different* edit of comparable magnitude to the same base model and
   sweep again. Probes moving under both are generically unstable; probes moving
   only under yours are candidate dependents.

Without the second control the top movers are mostly artifact, and a reviewer
will say so.

**Enumeration.** CounterFact is already ~21k subject-relation prompts — an
enumerated probe space, cheap to run in full on GPT2-medium. Add a WikiText
slice for perplexity drift (catches general capability damage that fact probes
miss). Cache the pre-edit pass once since the base model is fixed: top-100
log-probs plus log-sum-exp of the tail, so new metrics don't require re-running.
For the code domain, enumeration is graph traversal — walk k hops, template per
edge type, bank builds itself.

**Analytic shortcut worth trying.** ROME's update is low-rank at a single layer,
so its effect on any input is governed by that input's key vector's overlap with
the edit's key direction under covariance whitening. So you can *predict* which
probes move from key-space inner products, with no forward pass through the
edited model. Rank by overlap, compare to measured KL ranking. Correlation gives
a cheap blast-radius predictor plus a mechanistic story. Divergence is itself
the finding — propagation through something other than the key geometry the
method was designed around.

This is where Thread 1 stops being a separate project: representation distance
becomes the explanatory variable in the movement pipeline.

**Triage buckets** for significant movers, joined against edit metadata:

- shares the subject → expected propagation
- shares the relation, not the subject → relation-level leakage
- shares the object → attractor effect (edited value pulling unrelated prompts)
- shares nothing → the surprise bucket

Only the last needs manual reading, and its size is a result: a large
unexplained bucket means the edge vocabulary is missing a relation type.

## 7. Literature as of Sept 2026 — what moved

The field walked onto this patch in the last six months. Read in this order.

**KnowledgeSmith** (arXiv 2510.02392) — *read first.* Casts editing and
unlearning as one constrained optimization; structured interventions across
graph levels. Finds editing over-spreads while unlearning under-spreads; that
hierarchical branch structure imposes intrinsic ceilings on update
effectiveness, with higher/more central nodes limiting what's achievable; and a
consistency-capacity tradeoff where more data triggers collapse into
contradiction. **This is the out-degree hypothesis, tested and confirmed.** Don't
re-derive it. Build on it.

**JNO** (arXiv 2606.01610, Jun 2026) — argues desirable propagation and
unintended perturbation are two *coupled* pressures that prior methods treat
separately. That is the correct-vs-damage distinction, published as a method.
Their table: ROME at 53.8 logical generalization vs 36.1 ripple-specificity on
RippleEdits.

**RippleBench** (arXiv 2512.04144) — pipeline retrieving semantic neighbors and
generating questions at varying semantic distances. Claims no prior benchmark
measures propagation as a continuous function of semantic distance. The
distance-shell curve of §4, already built and released.

**Forgetting is Not Erasure** (arXiv 2606.02860) — much apparent forgetting is
*interface drift* between internal stages, not permanent erasure; recoverable by
stitching with transport keys. If it holds, "damage" is accessibility loss, not
destruction. Philosophically load-bearing for the ontology in §2.

**AI Engram** (Kwon et al., arXiv 2606.14997, ICML 2026 oral) — memory traces as
linear weight-space objects that compose arithmetically. Its compositional
hypothesis (edited models reach consistent equilibrium regardless of learning
sequence) is attacked in **arXiv 2607.24805**, which notes the evidence was
single and paired edits, so fatigue under sequential load is structurally
invisible. Path dependence under repeated editing is live and contested.

**EditPropBench** (arXiv 2605.02083) — dependency-labeled edit cascades with
explicit/literal/implicit/free-form strata; measures fraction of required
downstream updates correctly revised. But: scientific manuscripts, LLM editors,
not weights.

**CodePlan** — Bairi et al., *Proc. ACM Softw. Eng.* 1 (FSE), 2024, arXiv
2309.12499. Incremental dependency analysis, **change may-impact analysis**,
adaptive planning; the compiler is explicitly called the **oracle** that
validates the repository. The machinery exists, driving planners rather than
evaluating weight edits.

Also: WikiBigEdit (Thede et al. 2503.05683) on limits of lifelong editing;
Cohen et al., TACL 2024 for RippleEdits; pathway-dependent forgetting
(2606.15088) for acquisition-route asymmetry.

### What survives

Every distance measure above is semantic — RAG rank, embedding cosine,
LLM-generated MCQs. **None has a decidable oracle.** That was the original
insight and it survived. Backward direction: unclaimed. Weight edits + code
domain + dependency oracle: nobody has joined those ends.

### The narrowing

Measurement-over-method just got crowded. What didn't: **directional measurement
against a decidable oracle**. Stand there. Stay at "structured forgetting" and
three groups are already present.

## 8. Adjacent fields — this is a transfer, not a discovery

The symbolic literature solved this decades ago. Framing the contribution as
importing a formalism into the subsymbolic setting is defensible. Framing it as
"nobody thought of this" invites someone to produce Doyle 1979 and end the
conversation.

- **JTMS** — Doyle 1979, "A Truth Maintenance System," *Artificial
  Intelligence*. Explicit justification networks: premises → conclusion, with
  validity checked on retraction. This is backward-grounds tracking, 1979.
- **AGM belief revision** — Alchourrón, Gärdenfors, Makinson 1985. Contraction,
  revision, minimal mutilation; logical entailment as the oracle for what should
  change. Hansson 1999 on *kernel contraction* — minimal sets entailing the
  removed belief. Vocabulary for the meeting: "belief revision under bounded
  rationality, applied to a probabilistic model instead of a logical theory."
- **Program slicing** — Weiser 1981; Ryder & Tip on backward slices. **Backward
  slicing is the formal algorithm for generating the grounds probe set from a
  dependency graph.** Don't invent probe discovery; cite it.
- **Incremental compilation** — Tichy 1986, "Smart Recompilation," TOPLAS.
  Module dependency graph as decidable ground truth for what must be redone.
- **Why-provenance** — Buneman, Khanna, Tan 2001. Which inputs justify this
  output. Backward dependency tracking with query semantics as oracle.

Also: compression *is* generalization. A fixed-capacity system that never
forgets is a database and generalizes worse. So the project isn't fixing
forgetting — it's **specifying a norm for it**, i.e. which compressions are
legitimate. That framing is a research program rather than a bug hunt and is
much harder to poke at.

## 10. Frontier-model context (why it touches this work)

Not decoration — two real connections.

**Kimi K3** (Moonshot, Jul 2026): 2.8T total parameters, ~104B active,
activating 16 of 896 experts via Stable LatentMoE, ~2.5× K2's scaling
efficiency. KDA-dominant linear attention with periodic full attention, plus
Attention Residuals letting each layer selectively pull from arbitrary earlier
layers. 1M context, native multimodal.

**OpenAI Astra**: The Information reported (1 Sept 2026) a constrained
**recurrent depth** / looped transformer — same layers applied repeatedly to an
evolving hidden state. Unconfirmed by OpenAI; not in the system card. Pachocki:
computation depth within a factor of two of GPT-4, loops capped to preserve CoT
monitoring. Precedent exists (Nanbeige4.2-3B, ByteDance Ouro), so the technique
isn't exotic — the contested part is that latent computation isn't readable as
tokens.

**Why it matters here.** Extreme sparsity changes what an edit *means*: with 16
of 896 experts firing, which weights hold a fact is partly a routing question.
Superposition gains a discrete component, and every ROME/MEMIT result being
built on assumes dense MLPs. And recurrent depth is sharper still — if
computation moves into latent loops instead of emitted tokens, part of what the
instrument wants to check never surfaces as an answer. That's an argument *for*
this project, and the version of the pitch AI-safety people will care about
most. Read the LessWrong analysis on Astra's serial depth before making it out
loud, so it's made accurately.
