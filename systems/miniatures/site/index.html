Systems in Miniature

Problems from today's AI infrastructure and backends, each shrunk until it fits on one page: first the thing going wrong, then the fix, with the numbers to show the difference. Every one runs live; change the load and watch it break.

How these are made

Each simulation is a small Go program with tests that check the claim on its page. The same code is compiled to WebAssembly, so what runs in your browser is exactly what the tests check. Nothing is pre-recorded, and every slider re-runs it.

The models are deliberately small: a few rules, chosen so the effect is real and visible. They show why the fix works, not how fast any particular system is.

In a terminal: go run ./cmd/mini lists them; go run ./cmd/mini herd prints one side by side.
