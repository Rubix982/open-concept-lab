Local-first sync

Two phones share one note. On the train, both go offline and both keep editing. When they reconnect, the app has to merge two versions of the same text. The simple way, keeping whichever copy was saved last, quietly throws away the other person's work. A CRDT, a data type designed to merge cleanly, keeps every edit from both phones.

What to notice

In the example, phone A fixes "Teh" and adds "sly"; phone B fixes "jumsp" and adds "small", in the same place. Last writer wins keeps phone B's copy because it was saved last, so A's fix and A's word vanish, and the "Teh" that A deleted comes back.

The CRDT keeps both fixes and both words. Where both phones typed at the same spot, it puts one word before the other. Every phone uses the same tie-break, so they all agree. Each word stays in one piece instead of being shuffled letter by letter.

Try deleting a word on one phone while the other edits inside it. The edit still arrives; it just has nothing left around it.

How the model works

Each character gets a permanent id: a counter plus the phone that typed it. A Lamport clock means each phone's counter jumps past any counter it has seen. Typing records "put this character after the one with id X", and deleting records "hide the character with id X". Hidden characters stay in the list as markers so later edits can still point at them.

When two characters were put after the same one, the larger id goes first. Since every phone applies the same rule, they all end up with the same text, whatever order the edits arrive in. The tests check this for hundreds of random edit histories. This is RGA, the Replicated Growable Array (Roh and colleagues, 2011).

Last writer wins here keeps the copy saved most recently, exactly as it was when saved. See Kleppmann and colleagues, Local-first software (Ink & Switch, 2019), for why this matters for apps that work offline.

The CRDT is Go (sims/localfirst), compiled to WebAssembly; every keystroke replays the whole history through it. go run ./cmd/mini local-first prints the example's two merges in a terminal. Its tests check convergence, delivery in any order, and the claims on this page.
